> **Version**: 1.0 (initial draft verified against the source code, July 2026)
> **Route**: `/rendu-3d` — left-side menu "3D Render" (**3D DESIGN** section of the navigation bar, alongside "CAD" and "PDF3D")
> **Reference code (frontend)**: `frontend/src/pages/Rendu3DPage.tsx` (162 lines; assembles three building blocks); components `frontend/src/components/rendu3d/Rendu3DDropzone.tsx` (511 lines), `Rendu3DViewer.tsx` (371 lines), `Rendu3DControls.tsx` (288 lines), `rendu3dCapture.ts` (145 lines); `PlanCropper.tsx` (440 lines — **present in the folder but NOT used** by this page); client `frontend/src/api/rendu3d.ts` (68 lines); labels `frontend/src/i18n/locales/{fr,en}/rendu3d.json` (66 lines each, FR/EN parity)
> **Reference code (backend)**: **there is NO dedicated "rendu3d" router.** The module is wired to the **shared** endpoint `POST /api/erp/v1/cao/render`, defined by the `render_realistic` function in `backend/routers/cao.py` (621 lines; endpoint at line 539), which relies on the pure module `backend/routers/gemini_image.py` (176 lines; key + call to the image service).
> **Shared PostgreSQL tables (`public`)**: `ai_prepaid_credits` (the account's prepaid credit balance), `ai_usage_tracking` (usage tracking; the `feature` column receives the value `render3d`). No table of its own, no persistence of the produced image.
> **Scope**: this module takes a file **from your computer** — a **3D model** (GLB, GLTF, OBJ, STL, FBX), an **image** (PNG, JPG, WEBP) or a **PDF** — and produces a **photorealistic render image** generated by artificial intelligence (Google Gemini image service, "Nano Banana" line). The render is **billed to your account** at the marked-up actual cost and is **downloaded** as a PNG image. This is **not** the **CAD / 3D Modeling** module (manual drawing of the model, module 31), nor **PDF3D** (3D reconstruction of a set of plans by an external service, module 33), nor the **Takeoff** module (quantity takeoff on PDF, module 30).

*Terminology used in this manual:* "endpoint" refers to an API endpoint; "company" or "account" (also "tenant") refers to your organization, whose data is isolated; "render" refers to the photorealistic image produced by artificial intelligence; "credit balance" refers to the shared prepaid wallet that also powers the ERP's other artificial-intelligence features.

## 1. Overview

### 1.1 The module's mission

The **3D Render** module turns an ordinary file into a **photorealistic presentation image**, ready to show a client. In concrete terms, it lets you:

- **Import** a **3D model** (GLB, GLTF, OBJ, STL, FBX), an **image** (PNG, JPG, WEBP) or a **PDF** from your computer;
- **Frame the view**: for a 3D model, orient it with the mouse (orbit, zoom, pan) to the angle you want; for an image or a PDF, choose the page to use;
- **Adjust the render**: scene type (exterior / interior / object), free-text description of the materials and mood, quality level, resolution;
- **Generate** the render: the AI replaces the "mockup" look with realistic materials, lighting and mood, while **preserving the geometry** of the model and the camera angle;
- **Download** the produced image (PNG file) or **regenerate** it with different settings.

The render is produced **on demand, within moments** (synchronous processing: you wait for the result on screen), and **billed to your credit balance** at the service's marked-up actual cost. It works on a **usage basis** ("pay-as-you-go"): there is **no** included allowance.

### 1.2 How to access it

- Left-side navigation bar → **3D DESIGN** section → **3D Render** (image icon).
- Address: `/rendu-3d` (protected page, authentication required).
- The same 3D DESIGN section also contains **CAD** (`/cao2`) and **PDF3D** (`/hover`), which are separate modules.

The module is presented on **a single screen**, with no tabs, no sub-modules and no list: everything happens in one place, across three columns.

### 1.3 Roles and permissions

3D Render is deliberately **open to all signed-in users** of your company. The only real gate is **financial** (the credit balance), not the role.

| Situation | Effect |
|-----------|--------|
| **Any signed-in user of a company** | Can import a file, frame it, adjust settings and **generate a render** (no role or administrative-rights restriction). |
| **Platform super-administrator** | Also allowed, and **exempt from billing** (see §1.4). |
| **Consultation mode** (suspended subscription / read-only) | The render is **blocked**: generation is an unauthorized write in read-only mode and the ERP refuses it ("Consultation mode…" message) **before** any call. |
| **Fully blocked subscription** | Access denied (sign-out / re-authentication required). |

**Important clarifications:**

- **Company context is mandatory.** The endpoint requires your session to be tied to a company. An account with no company is refused the render (400 error "Missing tenant context").
- **No administrator / employee distinction.** Unlike other modules, there is **no** gate reserving the render for administrators. If an employee can open the page, they can generate (and therefore **spend credits**). Take this into account when managing your balance.
- **Instance with billing disabled.** On an internal installation where billing is turned off, the render works **for free** and the usage is still tracked. On the standard commercial ERP, billing is active.

### 1.4 Billing: usage-based, on your credit balance

Each render **debits real money** from your **prepaid credit balance** — the **same balance** as AI estimates, the AI Assistant and the CAD render. Key points:

- **A strictly positive balance is required.** Before launching the render, the ERP checks your balance. If it is **less than or equal to zero**, generation is **refused** (402 error "Insufficient AI credits for the render") **before** any call to the paid service. Because the render is a costly, non-essential action, this rule is **stricter** than for chat (which does tolerate a slight overage).
- **Cost = actual cost plus a 30% markup.** The amount billed is the gross cost of the image service (computed as precisely as possible, from the actual number of image tokens produced) **multiplied by 1.30**. A 4K render, which consumes more tokens than a 2K, therefore costs a little more — you pay for what you actually consume.
- **Cost shown in US dollars.** The render amount is shown **in US dollars** (the service bills in USD), not in Canadian dollars.
- **Debited after success.** The credit is debited **only after** the image is successfully produced. If the service fails, nothing is billed.
- **No server-side anti-double-billing key.** This endpoint has **no** server-side idempotency mechanism: protection against a double click is **entirely on the interface side** (the button locks during generation and the drop zone is frozen). Concretely, **if two render requests really went out in parallel, each would be billed**. In normal use, the interface prevents this case; still, avoid forcing repeated submissions.
- **Super-administrator exempt.** Their renders are not debited.

> **Bill this cost back.** As with the other AI features, the render consumes your prepaid balance. Plan to bill it back to your client as part of the engagement.

### 1.5 What the module does — and does NOT do

The module **does**: import a 3D model, an image or a PDF; frame a 3D view or choose a PDF page; adjust the type, description, quality and resolution; produce a photorealistic image by AI; show its cost; **download** the image (PNG); **regenerate** with different settings.

The module **does NOT**:

- **No conversational assistant.** There is no chat here: only a settings form. (Not to be confused with the CAD AI Assistant, module 31, which **draws** the model by voice.)
- **No persistence, no gallery, no history.** The produced image is **not saved** on the server nor listed. If you click "Regenerate" or change file, the previous render is **lost**. **Download it** if you want to keep it. (The `ai_usage_tracking` usage log is for accounting; it is not an image album.)
- **No PDF or CSV export, no printing.** The only output is the **PNG image download**.
- **No cropping (rectangular crop) on this page.** You frame either **through the 3D** (view orientation), or by taking **the whole image** or **a PDF page**. There is no "capture a portion of a plan" tool here. (That cropping tool exists elsewhere — see §5.1.)
- **No 3D reconstruction.** The module **does not build** a 3D model from a plan: it produces an **image**. To reconstruct a 3D model from a set of plans, use the **PDF3D** module (module 33).
- **No guaranteed identical result.** The render is **non-deterministic**: the AI preserves the geometry and the camera, but **reinterprets** the materials, lighting and context. Two renders with the same settings can differ. The result is a "marketing" image, to be reviewed.

### 1.6 The page's three columns

The screen consists of a **header** followed by **three columns** (stacked vertically on mobile, side by side on large screens):

| Column | Role | Content |
|--------|------|---------|
| **Left** (≈ 288 px) | **File drop** | Drag-and-drop zone / "Browse" button; page selector for a multi-page PDF. |
| **Center** (height ≈ 70% of the screen) | **Viewer / Preview** | Orientable 3D view (model), or image preview, or a prompt if there is no source. |
| **Right** (≈ 384 px) | **Controls panel** | Render settings (type, description, quality, resolution) and the generate button; then the result (image, cost, download, regenerate). |

**The processing of 3D files and the view capture happen entirely in your browser.** The server, for its part, only receives an **image** (never the original 3D file): it is this image — a capture of the 3D view, an imported image, or a PDF page — that is sent to the render service.

## 2. Interface

### 2.1 Header

At the top of the page: an icon (cube), the title **"3D Render"** and the subtitle **"Import a 3D model or an image and generate a photorealistic AI render."**

### 2.2 Left column — Drop zone

The drop zone has two faces depending on the situation: the **drop view** (default) and the **page-selection view** (only for a multi-page PDF).

#### 2.2.1 Drop view (default)

- A **dashed rectangle**, clickable, that also accepts **drag-and-drop** of a file. An upload-cloud icon is shown (replaced by an animated indicator while the file is read).
- Displayed texts: **"Drag a 3D file or an image here"**, then the formats **"3D: GLB, GLTF, OBJ, STL, FBX — Image: PNG, JPG, WEBP, PDF"**, an **"or"** separator, and a **"Browse"** button (folder icon).
- The file picker accepts the extensions: `.glb`, `.gltf`, `.obj`, `.stl`, `.fbx`, `.png`, `.jpg`, `.jpeg`, `.webp`, `.pdf`. Detection is done **by the file name extension**.

**What happens depending on the type of file dropped:**

| Type | Processing | Limit / error |
|------|-----------|---------------|
| **3D model** (`.glb`, `.gltf`, `.obj`, `.stl`, `.fbx`) | Loaded into the 3D viewer of the center column. | **Maximum 50 MB.** Beyond that: "File too large (maximum 50 MB)." |
| **Image** (`.png`, `.jpg`, `.jpeg`, `.webp`) | Resized (longest side scaled down to **2048 px** if needed) and re-encoded, then shown as a preview. | — |
| **Single-page PDF** | Page 1 is converted to an image directly (no selector). | If it cannot be read: "Unable to read this PDF." |
| **Multi-page PDF** | Switches to the **page-selection view** (below). | Same. |
| **Other extension** | Rejected. | "Unsupported file format." |

Below the zone, a **red banner** (alert icon) shows the error message where applicable.

> **Zone frozen during a render.** As long as a render is under way in the right column, the drop zone is **disabled**: this protects you from losing — by changing file — the image you are currently paying for.

#### 2.2.2 Page-selection view (multi-page PDF)

When a PDF contains several pages, the left column offers to **choose the page to use**:

- Title: **"Choose the page to use"** (document icon).
- **Preview** of the current page (the "Rendering page…" overlay appears while it is being prepared).
- **Counter**: "Page {n} / {total}".
- Navigation buttons: **"Previous"** (left arrow) and **"Next"** (right arrow).
- Primary button: **"Use this page"** (checkmark) — confirms the chosen page as the image to render.
- Secondary button: **"Choose another file"** (folder icon) — returns to the drop view.

### 2.3 Center column — Viewer / Preview

The center of the screen shows one of **three states**:

**A. 3D source — orientable viewer.** The imported model is shown in an **interactive 3D view** (browser engine, WebGL):

- **Mouse orientation**: orbit (rotation around the model), zoom (wheel) and pan.
- **Automatic framing**: on opening, the camera is placed in an isometric view to show the whole model; a ground grid and a cast shadow help you locate the volume.
- **Loading by format**: GLB/GLTF, OBJ, STL (normals are recomputed if missing) and FBX are supported. An OBJ without a materials file (MTL) is shown with a default material.
- **Loading overlay**: "Loading model…".
- **Error without crash**: if the file cannot be loaded, the viewer shows "Unable to load this 3D model." (the rest of the page stays usable).
- **Ready = condition to generate.** The generate button is active **only once the viewer has finished loading** ("ready" state). While the model is loading, no capture is possible — this avoids billing a render of an empty scene.

**B. Image source — simple preview.** An image or a PDF page is shown as a **centered image** (no 3D). It is this image, as is, that will be used for the render.

**C. No source — prompt.** As long as nothing is imported, the center shows an image icon and the message: **"Orient the model to frame the angle you want, then generate the render."**

> **The capture happens at "Generate".** For a 3D model, the image sent to the service is a **capture of the current frame** (the exact angle you framed), taken when you click "Generate render". It is capped at 2048 px per side to stay under the server limits. For an image or a PDF, it is the preview image itself that is sent.

### 2.4 Right column — Controls panel

The controls panel is **reset with each new file** imported: it clears the previous render and re-applies the suggested type.

It has **two states**: the settings (before the render) and the result (after the render).

#### 2.4.1 State 1 — Settings (before the render)

**1. Render type** ("Render type") — three buttons:

| Button | Hint | Use |
|--------|------|-----|
| **Exterior** | "Building seen from outside" | Façades, overview of a building. |
| **Interior** | "Room or interior layout" | Render of a room (materials + interior lighting). |
| **Object** | "Product or standalone object" | Product / catalog render, studio or contextual backdrop. |

*Automatic suggestion*: **Object** if the source is a 3D model, **Exterior** otherwise. You can always change it.

**2. Details and description (optional)** — a **text area** (up to **2000 characters**, 3 lines) to specify the desired materials and mood. Suggested example: "red brick siding, wood flooring, late-day lighting, contemporary furniture, neutral studio backdrop…". The more precise the description, the closer the render matches your intent.

**3. Quality** — three buttons:

| Button | Hint |
|--------|------|
| **Pro** *(default)* | "Best quality" |
| **Standard** | "Balanced" |
| **Fast** | "Economical" |

*Side effect*: choosing **Fast** automatically brings the resolution back to **2K** (Fast mode does not do true 4K).

**4. Resolution** — two buttons:

| Button | Hint | Availability |
|--------|------|--------------|
| **2K** *(default)* | "Fast, sharp" | Always. |
| **4K** | "Ultra-detailed (Pro/Standard)" | **Disabled** if Quality is set to **Fast**. |

**5. Generate button**: **"Generate render"** (sparkles icon). During processing, it becomes **"Generating render…"** with an animated indicator. It is **disabled** if a render is already under way, if no source is imported, or if the 3D viewer is not ready yet.

An **error banner** (alert icon) is shown above if generation fails (for example "Render failed. Try again." or the precise message returned by the server, such as an insufficient balance).

#### 2.4.2 State 2 — Result (after the render)

- **The render image** is shown (alt text: "Photorealistic render").
- **Cost note** (if the amount is greater than zero): **"This render cost: US${amount}"**.
- **"Download"** button (download icon): saves the image to your machine under the name `rendu-3d-<timestamp>.png`.
- **"Regenerate"** button (refresh icon): returns to the settings (settings and source are kept) to produce a **new** render. Note: the displayed render is then **replaced** — download it first if you want to keep it.

> **Anti-double-click lock.** The "Generate" button locks on the first click and releases only when it is done (success or failure). This is the main protection against double billing, since the server does not have one.

## 3. Step-by-step workflows

### 3.1 Render from a 3D model

**Prerequisite:** a 3D file (GLB, GLTF, OBJ, STL or FBX) of **50 MB maximum**; a **strictly positive** credit balance.

1. Open **3D DESIGN → 3D Render**.
2. In the left column, **drag-and-drop** your 3D file (or click **"Browse"**).
3. The model appears in the center viewer. **Wait** for the "Loading model…" overlay to disappear ("ready" state).
4. **Orient the view** with the mouse (orbit, zoom, pan) to frame the exact angle you want to render.
5. In the right column: choose the **Type** (Exterior / Interior / Object), enter a **description** of the materials and mood (optional but recommended), set the **Quality** and the **Resolution**.
6. Click **"Generate render"**. The capture of the current angle is sent to the service; wait a few moments.
7. The render is shown with its **cost in US$**. Click **"Download"** to save it, or **"Regenerate"** to try again with different settings.

### 3.2 Render from an image

**Prerequisite:** a PNG, JPG/JPEG or WEBP image; a strictly positive credit balance.

1. Open **3D Render** and **import** your image (drag-and-drop or "Browse").
2. The image is shown as a **preview** in the center (it is automatically scaled down to 2048 px per side if needed).
3. Set **Type**, **description**, **Quality** and **Resolution** in the right column.
4. Click **"Generate render"**, then **"Download"** or **"Regenerate"**.

*Tip:* to make a mockup screenshot, a sketch or a plan more realistic, describe the desired materials precisely in the **Details** field — the AI uses them to turn the flat image into a realistic scene.

### 3.3 Render from a PDF

**Prerequisite:** a PDF file; a strictly positive credit balance.

1. Open **3D Render** and **import** the PDF.
2. **If the PDF has only one page**, it is used directly (the preview is shown in the center): go to step 4.
3. **If the PDF has several pages**, the left column shows "Choose the page to use": navigate with **"Previous"** / **"Next"**, then click **"Use this page"** (or **"Choose another file"** to start over).
4. Set **Type**, **description**, **Quality** and **Resolution**, then click **"Generate render"**.
5. **Download** or **regenerate** the result.

### 3.4 Download, regenerate, start over

- **Download** saves the image under `rendu-3d-<timestamp>.png`. Since nothing is kept on the server, **this is the only way to keep your render.**
- **Regenerate** relaunches a render with the same source; the displayed render is **overwritten** by the new one. Download first if needed.
- **Change file** (a new import) resets the panel and **clears** the current render.

### 3.5 If the render is refused for insufficient credits

If a message indicates that your credits are insufficient (the render requires a **strictly positive** balance):

1. Go to **Configuration / Subscription** (module 28) to **top up your prepaid credit balance**.
2. Return to **3D Render** and relaunch generation.

No debit takes place as long as the balance is insufficient: the refusal happens **before** any paid call, so **there is no surprise**.

## 4. Reference

### 4.1 API endpoint

The 3D Render module **has no backend router of its own**: it calls the **shared** CAD endpoint. Do not look for a `routers/rendu3d.py` file — it does not exist.

| Method | Path | Guard | Role |
|--------|------|-------|------|
| POST | `/api/erp/v1/cao/render` | Authenticated + company required | Generates the render (Gemini image) and bills the cost. `render_realistic` function — `cao.py:539` |

- The module sends the field **`source: "render3d"`**. **This field changes exactly one thing**: the billing label written in the usage tracking (`feature` = `render3d` instead of `cao_render` for CAD). **The amount, the model, the debited wallet and the executed code are identical** in both cases: it is not a billing switch, only a tracking label.
- The interface client (`api/rendu3d.ts`) applies a **180 s timeout**; the image service on the server side itself has a **120 s** timeout.

### 4.2 Response codes and messages

| Code | Trigger |
|------|---------|
| **200** | Render produced. Response: image (embedded data), model used, cost billed in USD. |
| **400** | Missing company context; or invalid image (unreadable base64). |
| **402** | Insufficient credits — either the general authorization fails, or the balance is **not strictly positive** ("Insufficient AI credits for the render"). |
| **403** | AI feature refused; **or consultation mode** (read-only): the render is a blocked write. |
| **413** | Image too large (base64 too long, decoded image > 12 MB, or request body > 20 MB intercepted before processing). |
| **429** | Too many renders from your IP address (see §4.4). |
| **502** | The image service returned an error, an unreadable response, or **no image** (for example a safety block from the service). |
| **503** | Render not configured: **service key missing** ("AI render not configured (missing key)"), or billing unavailable. |
| **504** | Timeout on the image service side (120 s). |

Error messages stay **generic**: no internal technical detail is exposed.

### 4.3 Cost calculation

The cost always follows the same formula: **gross service cost × 1.30** (30% markup), billed in **US dollars**.

| Quality | Service model ("Nano Banana" line) | Gross cost per image token (USD) | Fallback flat rate per image (USD) |
|---------|-------------------------------------|-----------------------------------|-------------------------------------|
| **Pro** *(default)* | `gemini-3-pro-image` | 0.00012 | 0.14 |
| **Standard** | `gemini-3.1-flash-image` | 0.00006 | 0.06 |
| **Fast** | `gemini-2.5-flash-image` | 0.00003 | 0.04 |

- The gross cost is computed as precisely as possible: **actual number of image tokens produced × price per token** of the chosen level. A 4K render consumes more tokens than a 2K, so it costs a little more.
- If the service does not return the token count, the ERP applies the **fallback flat rate** per image of the chosen level.
- The final amount = `gross cost × 1.30`, rounded, then **debited from your balance**. The super-administrator is exempt.

*Indicative example:* a **Pro render at 2K** (~1120 tokens) costs about `1120 × 0.00012 × 1.30 ≈ US$0.17`; the same at **4K** (~2000 tokens) about `2000 × 0.00012 × 1.30 ≈ US$0.31`. The exact values vary with the scene.

### 4.4 Limits, bounds and quotas

| Item | Value |
|------|-------|
| 3D formats | **GLB, GLTF, OBJ, STL, FBX** (OBJ without MTL → default material) |
| Image formats | **PNG, JPG, JPEG, WEBP** |
| Document format | **PDF** (one chosen page) |
| Maximum size of a 3D model | **50 MB** |
| Image / capture resizing | Longest side scaled down to **2048 px** |
| Maximum size of the decoded image (server) | **12 MB** (beyond: 413) |
| Maximum length of the image field (base64) | **22,000,000 characters** |
| Request body cap (before processing) | **20 MB** (beyond: 413) |
| Free-text description | **2000 characters** |
| Quality levels | **Pro / Standard / Fast** |
| Resolutions | **2K / 4K** (true 4K requires Pro or Standard; Fast mode caps around 1K) |
| Rate limit per IP address | **10 renders per minute** (beyond: 429) |
| Server-side concurrency | **4 concurrent renders** maximum (queued beyond that) |
| Timeout (interface / service) | **180 s / 120 s** |
| Required balance | **Strictly positive** (> 0) |
| Server-side idempotency | **None** (anti-double-click protection in the interface only) |

### 4.5 Where the traces are found (data model)

- **`public.ai_prepaid_credits`** — your **prepaid credit balance** (the same as the AI Assistant, the estimates and the CAD render). The render draws the marked-up cost from it. This balance can be topped up (Configuration / Subscription module).
- **`public.ai_usage_tracking`** — the **usage log**: each render writes a row (user, model, image tokens, cost, duration, success). **The `feature` column is `render3d`** for this module (versus `cao_render` for the render launched from CAD). It is an accounting log, **not** an image gallery.
- **No other table.** The produced image is stored nowhere on the server.

### 4.6 Two render surfaces not to be confused

The same image module serves **two distinct surfaces**, with **different endpoints, wallets and markups**. They share only the image engine (`gemini_image.py`) and a nearly identical interface — **not** the billing.

| Aspect | **This module — ERP `/rendu-3d`** | **Public — Estimation Express `/estimation/rendu`** |
|--------|-----------------------------------|------------------------------------------------------|
| Endpoint | `POST /api/erp/v1/cao/render` | `POST /api/estimation/v1/render/{token}` |
| Authentication | ERP session (company required) | None (prepaid session token) |
| Debited wallet | **Account credits** (`ai_prepaid_credits`) | **Public prepaid wallet** of Estimation Express (shared with Express chat, **not** with the ERP) |
| Markup | **× 1.30**, in USD | **× 3.0**, converted to CAD |
| Anti-double-debit | Interface only | Server-side atomic reservation (concurrency lock) |

In other words: **there is no shared wallet between the ERP and Estimation Express.** The ERP render draws from your company's credits; the public Express render draws from a separate prepaid wallet.

### 4.7 Configuration dependency (infrastructure administrator)

The module is **inert as long as the image-service key is not set** on the server (environment variable `GOOGLE_GEMINI_API_KEY`). Without it, any generation returns **503 "AI render not configured (missing key)"**. Setting this key is an **infrastructure administrator** task, not a user action.

## 5. Integrations and FAQ

### 5.1 Links with other modules

- **CAD / 3D Modeling (module 31).** CAD has **its own "AI Render" button** that calls exactly the same endpoint (`/cao/render`), but from the model drawn inside the ERP. The **3D Render** module, by contrast, starts from an **imported file**. Both consume the same credit balance; only the tracking label differs (`cao_render` for CAD, `render3d` here).
- **PDF3D (module 33).** Not to be confused: PDF3D **reconstructs a 3D model and measurements** from a set of plans (external service, ~24 h, billed per structure). 3D Render **reconstructs nothing**: it produces an **image**. The CAD file that PDF3D lets you download can, conversely, be opened in 3D software and re-exported as GLB/OBJ to be **rendered** here.
- **Sales / Quotes (module 08).** A variant of this render tool is **built into a quote** ("Render from a quote"): that variant additionally offers a **rectangular crop** of a portion of a plan (the cropping tool that does not exist on the `/rendu-3d` page). Use the quote if you want to isolate an area of a plan.
- **AI Assistant and estimates (module 25).** 3D Render **shares the prepaid credit balance** with the AI Assistant and the estimates. A render reduces this common balance.
- **Configuration / Subscription (module 28).** This is where the **balance is topped up** and the subscription is managed. In **consultation mode** (suspended subscription), the render is **blocked**.

### 5.2 Frequently asked questions

**Do I need to be an administrator to generate a render?**
No. **Any signed-in user** of the company can generate a render — the only condition is a **strictly positive credit balance**. Keep in mind that an employee who generates **spends the company's credits**.

**How much does a render cost?**
The **service's actual cost plus 30%**, in **US dollars**, debited from your balance. It is **small and variable** (a few cents to a few tens of cents depending on quality and resolution), and shown after each render ("This render cost: US$…"). See §4.3.

**Why is the cost in US dollars and not Canadian dollars?**
Because the image service bills in US dollars. The debit is taken from your prepaid credit balance in that currency.

**Does the render reproduce my model exactly?**
It **preserves the geometry and the camera angle**, but **reinterprets** the materials, lighting and context. The result is **non-deterministic**: two renders with the same settings can differ. Treat it as a "marketing" image, to be reviewed — not as a technical survey.

**Where are my renders saved?**
Nowhere on the server. **There is no gallery and no history.** **Download** the image ("Download" button) if you want to keep it: a "Regenerate" or a file change erases it.

**Can this module build a 3D model from a plan?**
No. This module produces an **image**, not a 3D model. To reconstruct a 3D model from a set of plans, use **PDF3D** (module 33).

**Can I crop a portion of a plan before rendering it?**
Not on the `/rendu-3d` page: it uses the whole image or a full PDF page. The **rectangular crop** tool exists only in the **"Render from a quote"** variant (module 08).

**4K is greyed out — why?**
Because **Quality is set to Fast**, which does not do true 4K. Switch to **Pro** or **Standard** to enable 4K.

**Will I be billed twice if I click "Generate" several times?**
In normal use, no: the button **locks** during generation and the drop zone is frozen. Be aware, however: **the server has no idempotency safeguard** — if two requests really went out in parallel, each would be billed. Do not force repeated submissions.

**Nothing happens / the "Generate" button stays inactive.**
Check: (1) that a file is actually imported; (2) for a 3D model, that the viewer has **finished loading** ("ready" state); (3) that a render is not already in progress.

**The service is slow to respond.**
A render is usually fast but can take up to ~2 minutes depending on load. Past the timeout, an error is shown: try again.

**Can I generate a render in consultation mode (suspended subscription)?**
No. In read-only mode, generation is **blocked** (a render is a write action). Reactivate the subscription to use it.

### 5.3 Common troubleshooting

| Symptom | What to try |
|---------|-------------|
| "AI render not configured (missing key)" | The service key is not set on the server. **Infrastructure administrator** task. |
| "Insufficient AI credits for the render" | Balance ≤ 0. **Top up** the credit balance (Configuration / Subscription module), then retry. |
| "Consultation mode…" when clicking Generate | Subscription suspended (read-only). Reactivate the subscription. |
| "Unsupported file format." | Extension not in the list. Use GLB, GLTF, OBJ, STL, FBX, PNG, JPG, JPEG, WEBP or PDF. |
| "File too large (maximum 50 MB)." | The 3D model exceeds 50 MB. Lighten it (mesh reduction, remove unneeded textures). |
| "Unable to read this PDF." | The PDF is unreadable or protected. Re-export it or convert the page to an image. |
| "Unable to load this 3D model." | Non-standard 3D format or corrupted file. Re-export from your 3D software (GLB preferred). |
| The "Generate" button stays greyed out | No source, 3D viewer not ready yet, or a render already in progress. |
| "Render failed. Try again." | Transient service error (502/504) or network. Retry; if it persists, lower the quality/resolution. |
| Error 413 ("Image too large") | The capture / image exceeds the server bounds. Lower the source resolution or the extent of the view. |
| Too many renders refused (429) | You exceeded **10 renders per minute**. Wait a minute. |

## 6. Summary

- **The 3D Render module turns an imported file (3D model, image or PDF) into a photorealistic image** produced by artificial intelligence (Google Gemini image service, "Nano Banana" line). Access: **3D DESIGN → 3D Render** menu (`/rendu-3d`).
- **No dedicated backend router**: the module relies on the **shared** endpoint `POST /api/erp/v1/cao/render` (the same as CAD's "AI Render"). The `source: "render3d"` field changes **only the tracking label**.
- **3D processing and view capture are 100% in the browser**; the server only receives an **image** (never the 3D file), capped at 2048 px and 12 MB.
- **Three columns**: file drop (drag-and-drop, PDF page selector), viewer / preview (orientable 3D view or image), controls panel (Type, Details, Quality, Resolution → Generate → result).
- **Settings**: Type (Exterior / Interior / Object), free-text description (2000 characters), Quality (Pro / Standard / Fast), Resolution (2K / 4K; 4K requires Pro or Standard).
- **Usage-based billing** on the account's **prepaid credit balance**: **actual cost × 1.30**, in **US dollars**, debited after success. **A strictly positive balance is required** (otherwise 402, before any call). **No server-side idempotency**: anti-double-click protection is **in the interface**.
- **Open to any signed-in user** (no role restriction); **blocked in consultation mode**; super-administrator **exempt** from billing.
- **No persistence**: no gallery, no history, no PDF/CSV export. The only output is the **PNG download** (`rendu-3d-<timestamp>.png`). "Regenerate" or changing file **clears** the current render.
- **Non-deterministic result**: the geometry and the camera are preserved, but the materials and mood are reinterpreted — a "marketing" image, to be reviewed.
- **Not to be confused**: CAD (drawing the model, module 31), PDF3D (reconstructing a 3D model from plans, module 33), Render from a quote (with cropping, module 08). 3D Render produces **an image**, from an already-existing file.
- **Dependency**: inert without the service key (`GOOGLE_GEMINI_API_KEY`) → 503.
